# Gemini Client

Лёгкий клиентский мод для Minecraft **1.21.4** на Fabric: HUD, меню модулей и интеграция
с **HolyWorld LiteAPI** (In-Game API + публичный REST API).

## Возможности

| Модуль | Категория | Что делает |
| --- | --- | --- |
| `AutoFish` | Player | Автоматически вытаскивает удочку при поклёвке и закидывает заново |
| `ItemScroller` | Player | Shift + колесо мыши над слотом — быстрое перемещение стака |
| `FullBright` | Render | Яркость в пещерах клиентским эффектом ночного зрения |
| `ShulkerPreview` | Render | Сводка содержимого шалкера в подсказке предмета |
| `HitMarker` | Render | Маркер попадания у прицела |
| `TotemPopSound` | Render | Звук при срабатывании тотема |
| `TalismanHighlight` | Render | Подсветка талисманов в интерфейсе |
| `ScoreboardHP` | Render | Здоровье цели под прицелом |
| `ToggleSprint` | Movement | Спринт при движении вперёд |
| `KeyStrokes`, `WaterMark`, `InfoPanel`, `TargetHUD`, `ArmorHUD`, `HudStyle` | HUD | Элементы интерфейса |
| `CoinRate` | HUD | Курс обмена монет HolyWorld через REST API |
| `Zoom` | Render | Приближение камеры по удержанию клавиши (`C` по умолчанию) |
| `SeeInvisible` | Render | Невидимые существа видны полупрозрачной моделью |
| `TargetESP` | Render | Рамка вокруг цели, видна сквозь блоки |
| `Trajectories` | Render | Куда попадёт жемчуг, стрела или трезубец |
| `ItemSwap` | Player | Смена талисмана и сферы в левой руке |
| `Theme` | Render | Палитра акцента и стиль меню |

Меню открывается на **Right Shift**. ЛКМ по модулю — вкл/выкл, ПКМ — настройки.
Элементы HUD перетаскиваются мышью при открытом чате (`T`).

### Интерфейс

Цвета живут в одном месте — `theme/Colors`. Модуль `Theme` задаёт **акцент** (16 оттенков
палитры либо свой цвет), тёмную/светлую тему и **стиль меню**:

| Стиль | Как выглядит |
| --- | --- |
| `Panel` | Своя панель на каждую категорию — видно всё сразу |
| `List` | Широкая панель с поиском, модули сгруппированы по категориям |
| `Minimal` | Узкая колонка слева без панелей; включённое отмечено полосой |

Отрисовка вынесена в `ui/menu`: стиль рисует меню и возвращает **области строк**
(`MenuHitbox`), а обработка кликов одна на все стили и живёт в `ClickGuiScreen`.
Поэтому новый стиль добавляется одним классом, без копирования логики ввода.

Анимации — `animation/Easing` (15 кривых, включая cubic-bezier как в CSS) и
`animation/Animation` (таймовая, не зависящая от FPS); смена акцента плавная —
`theme/ColorAnimation`.

## Интеграция с HolyWorld LiteAPI

### Как это работает

Обмен идёт через [Minecraft Plugin Messaging](https://minecraft.wiki/w/Plugin_channels):
клиент шлёт Serverbound Plugin Message на канал `liteapi:feature-control`, сервер отвечает
Clientbound Plugin Message на тот же канал. **Тело пакета — сырая строка UTF-8 с JSON.**

> **Важно.** Тело пишется напрямую (`PacketByteBuf#writeBytes`), а не через `writeString`:
> последний добавил бы VarInt-префикс длины и сломал бы разбор на стороне сервера.
> См. [`LiteApiPayload`](src/main/java/wtf/gemini/liteapi/LiteApiPayload.java).

Запрос — метод `checkFeatures` со списком активных функций:

```json
{
  "id": "0f8fad5b-d9cb-469f-a165-70867728950e",
  "method": "checkFeatures",
  "payload": {
    "client": "gemini",
    "features": ["autofish", "itemscroller", "fullbright", "sprint"]
  }
}
```

Сервер возвращает **только заблокированные** функции из присланного списка:

```json
{
  "id": "0f8fad5b-d9cb-469f-a165-70867728950e",
  "ok": true,
  "payload": { "blocklist": ["fullbright"] }
}
```

`client` — фиксированная строка `gemini` ([`LiteApi.CLIENT_ID`](src/main/java/wtf/gemini/liteapi/LiteApi.java)):
сервер хранит по ней персональные блокировки, поэтому значение **не меняется между версиями мода**
и не является ни UUID, ни ником игрока.

Каждый модуль объявляет свой идентификатор функции через `getFeatureId()`. По умолчанию это имя
модуля в нижнем регистре без разделителей; если у функции есть общепринятое имя — оно задаётся
явно в конструкторе (например, `ToggleSprint` → `sprint`, `FullBright` → `fullbright`).

### Когда уходит запрос

| Событие | Что происходит |
| --- | --- |
| Подключение к серверу (`ClientPlayConnectionEvents.JOIN`) | Один запрос со **всем** списком функций |
| Включение функции с неподтверждённым статусом | Запрос ставится в очередь (см. ниже) |
| Выход с сервера | Состояние сбрасывается — старый блок-лист не действует |

**Лимит — 1 запрос в 10 секунд на игрока.** Он соблюдается конструктивно: обращения
схлопываются в один отложенный запрос, который уходит, как только окно лимита открылось
([`LiteApiClient`](src/main/java/wtf/gemini/liteapi/LiteApiClient.java)). Опрос «в цикле»
невозможен by design — периодического опроса сервера нет вообще.

Рекомендация API «проверять функцию при включении» реализована без задержки для игрока:
модуль включается сразу, а проверка встаёт в ту же очередь и применяется, когда ответ придёт.
Ждать до 10 секунд на каждый тумблер было бы хуже, чем доли секунды до ответа при том, что
основной путь и так закрыт запросом при подключении.

### Как скрываются заблокированные функции

Требование API: заблокированная функция должна быть **полностью скрыта** от игрока — убрана
из меню, настроек, подсказок и любых других UI-элементов. Запретить включение недостаточно,
поэтому модуль перестаёт существовать для интерфейса целиком:

| Место | Что сделано |
| --- | --- |
| Меню модулей | Заблокированные модули не рисуются; категория без видимых модулей не показывается |
| Настройки модуля | Недоступны — модуля нет в списке, раскрывать нечего |
| Экран «Управление» (ванильный) | Клавиша модуля удаляется из `GameOptions.allKeys` |
| Обработка клавиш | `ModuleStorage.tick()` пропускает заблокированные модули |
| HUD | Не отрисовывается; обработчик перетаскивания их не видит |
| Уведомления | `setEnabled` не показывает всплывашку для скрытого модуля |
| Конфиг | Сохраняется *намерение* игрока, а не принудительное «выключено» |

Два момента, на которые стоит обратить внимание:

1. **Клавиши.** `GameOptions.allKeys` объявлено `public final`, а Fabric API снимает final
   в рантайме своим миксином. Поэтому массив пересобирается рефлексией
   ([`GameOptionsAccess`](src/main/java/wtf/gemini/util/GameOptionsAccess.java)) — своя миксина
   здесь не нужна и не зависит от порядка применения миксинов. Если запись почему-то не удалась,
   клиент продолжает работать, просто клавиша останется видна в списке.
2. **Возврат состояния.** Модуль запоминает, был ли он включён до блокировки, и возвращает
   это состояние, когда сервер снимает блокировку. Так же ведёт себя и конфиг.

### Поведение при ошибках

**Fail-open.** Пока сервер не подтвердил блокировку, не скрывается ничего: на серверах без
LiteAPI запрос остаётся без ответа, и клиент обязан работать как обычно. Блок-лист становится
авторитетным только после успешного ответа.

| Ситуация | Поведение |
| --- | --- |
| Сервер не поддерживает LiteAPI | Запрос уходит в никуда, ничего не скрывается |
| `BAD_REQUEST`, `NOT_FOUND`, `INTERNAL_ERROR` | Пишется предупреждение в лог, ничего не скрывается |
| `RATE_LIMITED` | Следующий запрос уйдёт не раньше чем через 10 секунд |
| Ответ не пришёл за 5 секунд | Считается таймаутом; **поздний ответ всё равно принимается** |
| Некорректный JSON | Пакет отбрасывается, пишется предупреждение |

Push-события (`{"event": ..., "payload": ...}`) не являются ответами на запросы и не путаются
с ними: `LiteApiResponse.parse` возвращает `null`, если в теле нет поля `ok`.

## Публичный REST API

Модуль `CoinRate` показывает курс обмена монет с `https://api.holyworld.me`:

- запросы уходят **только когда игрок на сервере HolyWorld** (проверяется адрес подключения);
- обновление раз в минуту, повторный запрос не стартует, пока летит предыдущий;
- запрос выполняется асинхронно, результат читается из `volatile`-полей — поток рендера не блокируется;
- строка пересобирается только при появлении новых данных, в кадре аллокаций нет.

Публичные методы не требуют авторизации и не имеют прикладных лимитов; используемые здесь —
`GET /v1/coins-trades?limit=2`.

## Сборка

Нужен **JDK 21** (Minecraft 1.21.4 требует именно 21 — на 17 Loom падает с
`Minecraft 1.21.4 requires Java 21`).

```bash
./gradlew build
```

Готовый мод: `build/libs/gemini-client-<версия>.jar` (без `-sources`).

Версия мода задаётся в `gradle.properties` (`mod_version`) и подставляется в `fabric.mod.json`
при сборке; в рантайме она читается из метаданных мода, а не дублируется строкой в коде.

## Структура проекта

```
src/main/java/wtf/gemini/
├── Gemini.java              точка входа, связывание подсистем
├── Module.java              базовый модуль: состояние, настройки, клавиша, блокировка
├── register/ModuleStorage   реестр модулей, тик, отрисовка HUD
├── liteapi/                 интеграция с In-Game API
│   ├── LiteApi              константы протокола
│   ├── LiteApiPayload       CustomPayload: сырой UTF-8 JSON
│   ├── LiteApiRequest       сборка запроса checkFeatures
│   ├── LiteApiResponse      разбор ответа и push-событий
│   ├── LiteApiClient        отправка, корреляция по UUID, таймаут, rate limit
│   └── FeatureGate          применение блок-листа к модулям и клавишам
├── holyworld/HolyWorldApi   клиент публичного REST API
├── hud/                     HUD-элементы (HudModule — позиция и перетаскивание)
├── modules/impl/            игровые модули: player, render, movement
├── setting/                 BooleanSetting, FloatSetting
├── config/ConfigManager     конфиг gemini.properties с отложенной записью
├── ui/ClickGuiScreen        меню модулей
├── mixin/                   точечные миксины (2 инжекта + 2 accessor)
└── util/                    Render2D, GameOptionsAccess
```
